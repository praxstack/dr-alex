# Memory-safety evidence note — 2026-08-23

## Scope

This note checks the memory-safety recommendations in the local architecture review and therapist-stack audit against current primary standards, official guidance, original research, and systematic reviews. It covers lifecycle/provenance, memory classes, ingest/replay, retrieval, correction/deletion, privacy, crisis-path independence, and evidence limits. It intentionally does not reproduce or assess any private conversation or clinical record.

This is non-authorizing library material. Its implications describe future policy/design work
unless a governing v3 artifact explicitly incorporates them.

**Reading rule:** “verified” means the cited source supports the principle; it does **not** mean the source validates this repository’s exact implementation. “Engineering inference” is a design conclusion drawn from the reports plus the cited principle.

## Non-authorizing implications for future work

1. Keep the review’s lifecycle fields: immutable source/message ID; source and derivation IDs; user-stated vs inferred; event/recorded time; validity/supersession; purpose, sensitivity, retention; and deletion state. Add a protected provenance/audit record rather than relying on a rendered memory file as the only source of truth.
2. Implement exactly one replay-safe post-commit ingest route. A unique source key plus transactionally recorded receipt is the minimal design; disclose it as at-least-once ingestion with idempotent effects, not exactly-once delivery.
3. Keep raw transcripts, events/episodes, editable profile/preferences, current-state claims, and short-lived inferences separate. This is a safety and lifecycle boundary, not a diagnostic model and not a claim of clinical benefit.
4. Apply authorization, purpose/sensitivity, deletion, validity, and identity/thread filters before ranking. Retrieval scores, recency, and model confidence are routing signals—not proof a recalled claim is true. Show dates/provenance and surface unresolved conflicts.
5. Require user-facing inspect/correct/forget/export controls; exercise deletion through indexes and restore workflows with synthetic records. Keep crisis triage and hand-off able to execute when memory retrieval, indexes, or the memory store are unavailable.
